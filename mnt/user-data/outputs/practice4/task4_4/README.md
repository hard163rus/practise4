# Задание 4-4: Анализ памяти и процессов — README

## Описание

Анализ карты памяти программы с динамическим выделением памяти
из задания 4-1 с помощью утилит `pmap`, `/proc/[PID]/maps`, `strace`, `ps`.

---

## Наблюдения

### 1. Сегменты виртуальной памяти процесса

Вывод `pmap` и `/proc/[PID]/maps` показал, что адресное пространство процесса
делится на несколько чётко выраженных областей:

- **Код программы** (`r-xp`) — исполняемые инструкции самой программы, только для чтения и выполнения.
- **Данные программы** (`rw-p`) — глобальные и статические переменные, доступны на чтение и запись.
- **Heap (куча)** (`[heap]`, `rw-p`) — область динамической памяти. Именно сюда `malloc()` помещает выделяемые блоки. После вызова `malloc(100 * sizeof(int))` размер heap увеличился.
- **libc** — стандартная библиотека C, отображённая в адресное пространство процесса. Содержит реализации `malloc`, `printf` и других функций.
- **Stack (стек)** (`[stack]`) — автоматические переменные и адреса возврата функций.

### 2. Как malloc взаимодействует с ядром

`strace` показал, что `malloc` при первом вызове запрашивает у ядра память
через системный вызов `brk()` — он сдвигает границу heap вверх.
Для больших блоков `malloc` использует `mmap()` напрямую.
Функция `free()` не возвращает память ядру немедленно — она помечает блок
как свободный внутри heap для повторного использования.

### 3. VSZ vs RSS

- **VSZ** (Virtual Size) — полный размер виртуального адресного пространства процесса (~2564 kB). Включает все отображения, в том числе те, которые ещё не загружены физически.
- **RSS** (Resident Set Size) — реально занятая физическая RAM (~512 kB). Намного меньше VSZ, потому что страницы загружаются в RAM только при обращении к ним (demand paging).

### 4. Вывод

Динамически выделяемая память через `malloc` находится в сегменте heap.
Каждый вызов `malloc` потенциально расширяет heap через `brk()`.
Вызов `free()` освобождает память для повторного использования внутри процесса,
но не обязательно возвращает её операционной системе немедленно.
Утилиты `pmap` и `/proc/[PID]/maps` наглядно показывают эту структуру.
